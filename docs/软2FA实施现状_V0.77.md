## 1. 软 2FA 已落地现状（V2.0.69 → V2.0.77.6）

主站的"软 2FA"实际上是 V2.0.69 A+D+B 邮件版安全方案 + V2.0.77.6 设备信任双因子 的组合落地，已 **不再硬性全员 2FA**（V2.0.67 强 2FA 已 .68 回滚，教训"不增管理员登录摩擦"）。

### 1.1 触发场景

| # | 触发条件 | 强制 / 可选 | 验证方式 |
|---|---|---|---|
| 1 | **新设备登录**（设备指纹未命中） | **强制** | 邮箱 OTP（6 位数字，10 分钟有效） |
| 2 | **改密码**（已登录） | **强制**（绑邮箱时） | 邮箱 OTP |
| 3 | 密码重置（forgot-password） | 强制 | 邮件链接一次性 token（1 小时有效） |
| 4 | **信任设备** | 跳过 | 仅 UA + IP 段指纹（V2.0.77.6 算法） |

### 1.2 关键端点

| 端点 | 用途 | 鉴权 |
|---|---|---|
| `POST /api/auth/captcha` | 算术图形验证码 | 公开 |
| `POST /api/auth/login` | 登录（含可选 `emailOtpCode` 字段） | 公开 |
| `POST /api/auth/device-otp/send` | 新设备 OTP 触发 | 公开（按用户名查询） |
| `POST /api/auth/change-password-otp/send` | 改密码 OTP 触发 | 需已登录 |
| `POST /api/auth/change-password` | 改密码（`emailOtpCode` 必填） | 需已登录 |

### 1.3 流程（前端 portal.html 已实现）

```
用户输入用户名+密码+算术 captcha → POST /api/auth/login
  ├─ 信任设备命中 → 返回 token（30 天有效后自动重新评估）
  └─ 未信任设备 → 返回 deviceOtpRequired=true（HTTP 200）
        ├─ 前端自动 POST /api/auth/device-otp/send → 邮箱收到 6 位码
        ├─ 用户输入 OTP → 再次 POST /api/auth/login 带 emailOtpCode
        │     ├─ 验证成功 → 落 30 天设备信任记录 → 返回 token
        │     └─ 验证失败 → 弹"邮箱码错误"重试（captchaTicket 免重复算题）
        └─ 前端弹 modal：标题「新设备登录，请输入邮箱验证码」+ 倒计时 60s 重发
```

### 1.4 安全强度

| 维度 | 状态 |
|---|---|
| 抗撞库 | ✅ 算术 captcha（V2.0.66） |
| 抗暴力破解 | ✅ RateLimit（10次/小时/IP）+ 账户锁定 |
| 抗会话劫持 | ✅ JWT HS512 + 黑名单 + refresh_token 防重放 |
| 抗新设备盗用 | ✅ 邮件 OTP（强制）+ UA+IP 双因子指纹（V2.0.77.6） |
| 抗内部滥用 | ⚠️ 已登录后的敏感操作（改邮箱/改角色/删除公司）**未触发 OTP** —— 见 §3 PRD |
